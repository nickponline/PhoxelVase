the-finals project · explainer

Destructible buildings, from blueprint to rubble

This page explains the full system, step by step. One program makes buildings that can break. A second program breaks them with bullets and explosions. The text uses simple technical English. Each special term has a definition where it first occurs.

1. What this is

The video game THE FINALS has buildings that you can destroy completely. Its studio, Embark, makes these buildings with a commercial 3D tool, Houdini, and an in-house tool set, "Building Creator". This project does the same work with free code.

The project has two parts:

  • bgen (Python). It makes buildings. Each building comes already cut into small pieces.
  • rubble (Rust). It is a physics engine. It moves the pieces and decides when the building breaks.
Physics engine: a program that calculates how objects move, fall and hit each other, step by step in time.

The two parts share one file type, .bld. bgen writes it. rubble reads it.

This is a single-player demo. It has no network or multiplayer code.

3. Part 1: make a building (bgen)

bgen does the job of Houdini plus Building Creator. It needs no 3D program. It runs from a command line.

Five of the six presets. The sixth preset is "office" (shown in the large images on this page).

Preset: a set of default values for one type of building, for example floor height, materials, window style and room types.

3.1 Start with a spec and a seed

You describe a building in a spec file. The file uses YAML.

Spec (specification): a short text file that tells bgen what to make. YAML: a plain-text format for settings, with one "key: value" per line.

A spec can give exact values or ranges. For a range, for example floors: [8, 15], bgen picks a value. A seed controls these choices.

Seed: a whole number that starts the random number generator. The same spec and the same seed always give the same building, byte for byte. 
name: building4
preset: tower
blockout:
  - {footprint: [[0,0],[40,0],[40,32],[0,32]], floors: 4}    # podium
  - {footprint: [[7,3],[33,3],[33,29],[7,29]], floors: 40}   # main shaft
  - {footprint: [[10,6],[30,6],[30,26],[10,26]], floors: 48} # setback
  - {footprint: [[14,10],[26,10],[26,22],[14,22]], floors: 52} # crown
nodes:
  - floors: {}
  - exterior_walls: {bay_width: [3.0, 3.6]}
  - columns: {grid: 6.0, size: 0.8}
  - rooms: {min_room: 14.0}
  - stairs: {cores: 1}
  - openings: {windows: {style: ribbon}}
  - roofs: {flat: {parapet: 1.2}}

Part of bgen/specs/building4.yaml, a 52-storey tower.

3.2 Make the blockout

The first step makes the blockout.

Blockout: the rough shape of the building, with no walls or windows. Here it is a list of masses. A mass is a footprint (the outline on the ground, seen from above) and a number of floors.
  1. bgen reads each mass.
  2. For each floor level, bgen joins all masses that reach that level. The result is the floor outline for that level.
  3. bgen finds the straight outside edges of each floor outline. These edges are the facades (the outside faces of the building).

3.3 Add features with feature nodes

Next, bgen runs a chain of feature nodes. This copies the design of Building Creator.

Feature node: a small function that adds one type of architectural part. All nodes have the same inputs and outputs. Each node receives the building so far and returns it with its new parts added.
NodeWhat it adds
floorsOne concrete slab (flat floor plate) per floor.
exterior_wallsOutside walls. It divides each facade into bays (vertical strips, 3–4.5 m wide). Windows align with the bays.
columnsVertical posts on a regular grid, and at corners.
roomsDivides each floor into rooms with BSP. Adds inside walls and a name for each room (office, meeting, corridor…).
stairsA stair core that goes through all floors. It cuts holes in the slabs above.
openingsCuts windows and doors into the walls. Adds a glass pane in each window. Makes sure that a person can reach every room.
roofsFlat roofs with a low edge wall (parapet), or pitched roofs (gable, hip, kyoto).
balconiesSlabs that stick out from the facade (cantilevers), with a parapet.
manualYour own changes from a file: add, move or delete a part. The changes stay after you make the building again.
BSP (binary space partition): cut an area in two, then cut each half in two again, until each part has the correct size. Cantilever: a part that has support at one end only.

3.4 Every part is a panel

Every wall, slab, column, roof plane and stair is a panel. This is the most important idea in bgen.

Panel: a flat 2D outline (the profile) plus a thickness. bgen pushes the profile out by the thickness to make a solid. This operation is called extrusion.

This method has three advantages:

  • Each solid is watertight: its surface is closed, with no gaps.
  • Holes for windows and doors are simple 2D cuts.
  • The difficult 3D problems become easier 2D problems.

3.5 Pre-fracture: cut each panel into chunks

bgen cuts the building into pieces before the game starts. This is pre-fracture. THE FINALS uses the same method, because cutting objects during play is slow and unpredictable.

Chunk: one small piece of a panel. A chunk is the smallest part that can break off. An office has about 5,000 chunks.

Every chunk must be convex. Physics engines can test collisions between convex shapes quickly and reliably.

Convex: a shape with no dents or holes. A straight line between any two points inside the shape stays inside the shape. A square is convex. An "L" shape is not.

bgen does these steps for each panel:

  1. Convex decomposition. Cut the profile into convex parts. bgen divides the profile into triangles, then joins triangles while the result stays convex.
  2. Seed points. Scatter random points on the profile. The material sets the distance between points (concrete about 0.9–2 m, brick 0.6–1.5 m).
  3. Voronoi cells. Make one Voronoi cell around each point.
  4. Clip. Intersect each convex part with each cell. The intersection of two convex shapes is always convex. Thus every result is convex.
  5. Clean up. Join very small or thin pieces to a neighbor.
  6. Extrude. Give each 2D piece the thickness of the panel. The result is a convex prism.
Voronoi cell: the area that is nearer to one seed point than to all other seed points. The cells together look like cracked mud. Convex prism: a convex 2D shape pushed straight out into 3D, like a coin or a brick.

Each chunk is three things at the same time:

  • the mesh that you see (its triangles),
  • the collision shape that the physics engine uses (the same convex prism),
  • a mass. bgen calculates the mass, the center of mass and the inertia from the material density.
Center of mass: the point where the object balances. Inertia: how hard it is to make the object turn.

Glass panes are not cut. Each pane is one chunk. The engine breaks it into particles when anything hits it.

3.6 Connect the chunks: the connection graph

Next, bgen finds which chunks touch. It records this in a connection graph.

Graph: a set of points (nodes) and lines between them (edges). Here each node is a chunk. Each edge is a contact between two chunks. People also call an edge a bond or a joint.

For each edge, bgen records:

  • the contact area (in m²),
  • the contact center and the direction of the contact,
  • the strength: contact area × material bond strength. The unit is newtons (N), a unit of force.
MaterialDensity (kg/m³)Bond strength (MPa = million N/m²)Structural?
concrete24008yes
brick19005yes
wood6003yes
metal (steel)780020yes
glass25000no (carries no load)

A bond between two different materials has 70% of the strength of the weaker material.

Chunks that touch the ground are anchors.

Anchor: a chunk that is fixed to the ground. All weight must flow down to the anchors. A chunk with no path to an anchor will fall.

3.7 Validate the building, and make sure it stands

bgen checks every building before it saves it. A failed check stops the build with an error report.

  1. Geometry checks. Every chunk is convex and watertight. No two chunks overlap. The chunk volumes of each panel add up to the panel volume.
  2. Connectivity check. Every structural chunk has a path to an anchor.
  3. Room check. A person can reach every room through doors and stairs.
  4. Stability check. bgen asks rubble's stress solver: "Can the undamaged building hold its own weight?" (See 5.5.) Each edge gets a utilization.
  5. Reinforcement. If an edge has utilization of 0.5 or more, bgen makes that edge stronger, then checks again. This is like adding steel bars to concrete. bgen repeats this up to 8 times.
Utilization: load on an edge ÷ strength of the edge. 0.2 means "20% of its limit". 1.0 or more means "it breaks". The target for a new building is less than 0.5, so the building has a safety margin.
A very tall building cannot always reach 0.5. For building4 (52 floors), the spec sets stability: {accept_util: 0.8}. bgen still reinforces toward 0.5, but accepts a result below 0.8. Building4 reaches 0.75.

3.8 Save the output files

bgen writes one folder per building, for example assets/buildings/office_1/:

FileContents
building.bldEverything the engine needs, in one binary file. See section 4.
building.glbThe meshes in glTF format, one node per chunk. Use it to look at the building in other 3D programs.
manifest.jsonThe spec, the seed, statistics, the room list, timings and the validation report.
renders/*.pngAbout 20 images: 4 corner views, front, side, top, fractured, exploded, cutaways, floor plans, graph, stress.
glTF (.glb): a standard file format for 3D models. Most 3D programs can open it.

A 5-floor office takes about 1.5 s to make, or about 5 s with all images. Houdini needs 4–6 minutes for each change.

4. The .bld file: the contract between the two parts

The .bld file is the only link between bgen and rubble. Both sides must agree on its exact layout. This agreement is the contract.

The file has a header and a list of sections. Each section is a list of fixed-size records:

SectionOne record =
METAText (JSON): name, seed, materials table, rooms, bounds.
ELEMOne panel: type (wall, floor…), material, floor number, position.
CHNKOne chunk: mass, volume, hit points, center of mass, inertia, flags, and where to find its shapes.
HVRT / HPLNCorner points and face planes of the collision shapes.
MVRT / MIDXVertices and triangles of the visible meshes.
EDGEOne bond: the two chunks, contact area, strength, center, direction.
ANCHWhich chunks are anchors (1 bit per chunk).
SOCKSockets: places to attach extra objects, for example window frames or balcony rails.

The header also holds a hash of all sections. rubble does not load a file if the hash is wrong.

Hash: a short number calculated from the file contents. If one byte changes, the hash changes. It shows that the file is not damaged.

The chunk flags tell the engine about special chunks: ANCHOR (fixed to the ground), INDESTRUCTIBLE (cannot break), GLASS (breaks on any hit), COSMETIC_ATTACHED (decoration that carries no weight, for example stair steps).

5. Part 2: destroy a building (rubble)

rubble is the physics engine. It is written in Rust, a fast programming language. It uses the open-source library Rapier for the motion of falling pieces. The code for damage, stress and collapse is new.

Rapier: a Rust library that simulates rigid bodies. A rigid body is an object that moves and turns but does not bend.

5.1 Load: an intact building costs almost nothing

When rubble loads a building, every chunk becomes a static collider.

Static: fixed in place. A static object can be hit, but it does not move, so the engine does not calculate its motion. Collider: the shape that the engine uses to find contacts.

Only pieces that break free become moving objects. This is the main reason why the engine is fast: an intact building costs only a few microseconds per step.

rubble also solves the stress of the intact building fully at load time (see 5.5). Thus nothing breaks by mistake in the first second.

5.2 One tick, step by step

The engine works in ticks. One tick is 1/60 of a second.

Tick (time step): one update of the world. The engine does 60 ticks per second of game time.

Each tick does these steps in this order:

5.3 Damage: bullets and explosions

Each chunk has hit points (HP). Each bond has a health value.

Hit points (HP): a number that goes down when the chunk takes damage. At 0, the chunk is destroyed. Larger chunks have more HP.
  • Bullets. A bullet is either a hitscan or a ballistic projectile. It damages the chunk that it hits, and a little of the neighbor chunks.
  • Explosions. An explosion damages all chunks in a sphere. Damage is full near the center and goes down to zero at the edge. Chunks behind other chunks get less damage.
  • Cracks. An explosion also damages bonds out to 1.5 × its radius. Thus it can break whole slabs loose without destroying them. Then the slabs fall in one piece.
  • Glass breaks on any hit. Indestructible chunks ignore damage.
Hitscan: the shot hits at once, along a straight line. Ballistic: the shot is an object that moves through the air for some time, for example a rocket.

5.4 Connectivity: is there still a path to the ground?

When a chunk or a bond breaks, the engine marks the nearby chunks as dirty.

Dirty: changed, so the engine must check it again.

For each dirty chunk, the engine follows the bonds outward. It stops when it finds an anchor. If it does not find an anchor, the chunks that it visited form a loose group. The group will fall.

This search only visits the part of the building near the damage. Thus it is fast, even in a large building.

5.5 Stress: can the remaining structure carry the weight?

Connectivity is not sufficient. A building can still connect to the ground through one thin column. Real buildings fall when their supports are too weak. The stress solver handles this.

Stress solver: code that calculates how much load each bond carries. Load: the force that a part must carry, mostly the weight of everything above it.

The solver treats the building like an electrical circuit:

The solver works in these steps:

  1. Give each chunk a load equal to its weight (mass × 9.81).
  2. Solve the circuit equations. The solver uses conjugate gradient. It starts from the answer of the last tick (a warm start), so it needs few steps.
  3. Calculate the load in each bond from the result.
  4. Add a bending load for parts that stick out, for example balconies.
  5. Calculate the utilization of each bond.
  6. If a bond stays above 1.0 for 0.25 s, break it. Break at most 8 bonds per tick, the worst first. Thus a collapse spreads over several frames and looks natural.
Conjugate gradient: a standard method that solves a very large set of linked equations in small repeated steps. Warm start: begin from a previous answer instead of from zero. Bending: a part that sticks out, like a shelf, tries to turn at its support. The joint at the support carries extra load.

Three rules make the model more realistic:

  • Compression is stronger than pull. A bond that carries weight straight down is 10 times stronger. Real concrete is much stronger in compression (squeeze) than in tension (pull).
  • Bending uses whole sections. The solver adds up the bending of all bonds along one cut line (for example, where a wall meets a column). One small contact does not count as a full beam.
  • Break only on a good answer. The engine breaks bonds only after the solver converges, or after 20 ticks. This stops false breaks from an unfinished calculation.
Converge: the repeated steps of the solver come close enough to the exact answer.

bgen uses the same solver offline in its stability check. Thus the generator and the engine agree about which buildings stand.

5.6 Fall and break up

A loose group of chunks is a cluster.

Cluster: a group of connected chunks that moves as one rigid body. One falling 5-storey section is one cluster, not 2,000 separate pieces. This keeps the engine fast.
  1. Warning. The engine sends a CollapseWarning event. The group waits 0.3–1.0 s (longer for heavier groups). A game can show dust and play a creak sound in this time.
  2. Promotion. The static colliders of the group go away. One moving body takes their place. Its mass and inertia are the sum of the chunk values from the .bld file.
  3. Fall. Rapier moves the body with gravity. If an explosion caused the break, the body starts with the push of the explosion.
  4. Impact. When the body hits something hard, the engine runs the stress solver on the body itself. The sudden stop acts like extra weight. Bonds that are too weak break.
  5. Split. The body divides along the broken bonds. Each new part becomes its own body and keeps its speed.

Small destroyed chunks become small flying debris or disappear as particles. Larger destroyed chunks always disappear as particles.

Debris: small broken pieces that fly and fall.

5.7 Settle and freeze: rubble changes the map

In THE FINALS, rubble stays where it lands. rubble does the same.

  • A body that stays still for 0.5 s (and is at least 2 s old) freezes.
  • Its chunks become static colliders again, at their new position. You can still shoot them.
  • Small debris disappears after some seconds.
  • A body does not freeze while the thing under it still moves.
  • If the support under frozen rubble goes away (destroyed, broken loose or removed), the rubble thaws: it becomes a moving body again, falls, and freezes again where it lands.
Thaw: turn frozen pieces back into a moving body. The engine tests support by moving the pieces down 3 cm: if they touch something that they do not touch when moved up 3 cm, something holds them up. Freeze: turn a moving body back into fixed (static) pieces. This removes its cost from the physics step.

The engine also has budgets: for example, at most 512 moving clusters. If there are too many, the smallest or oldest pieces freeze early or disappear.

Budget: a fixed limit on work or objects. It keeps every tick fast.

6. See the results

6.1 Collapse animations

These animations come directly from the engine. The scenario runner plays a scenario, saves the chunk positions of every 4th tick, and the bgen renderer draws each frame. Nothing is animated by hand.

In each collapse, a grid of charges goes off at 0.5 s, 1.2 m above the ground. The charges destroy the ground floor. Then the steps of section 5 take over: connectivity, stress, warning, fall, impact and freeze.

If your system asks for reduced motion, this page shows still contact sheets in place of the animations.

6.2 Scripted scenarios

A scenario is a YAML file that lists buildings and timed actions, for example "at 0.5 s, explode at this point". The scenario runner plays it, saves every frame and makes a GIF and a contact sheet.

Scenario: a repeatable test of destruction. Contact sheet: one image with several key frames side by side.

6.3 The interactive viewer

The viewer is a desktop program. It uses Bevy, a Rust game engine, to draw the world. You can fly the camera, shoot, set off explosions and show the stress of every bond as color.

8. Known limits

Caution: the stress model is a simplification for a game. It is not an engineering tool. Do not use it to judge real buildings.
  • No hinges and no sag. A bond is either fully rigid or broken. A slab cannot hang from one edge or bend down slowly.
  • Few pillars can hold too much. After very large damage, the stress answer takes several seconds to catch up. Columns are also strong in compression, and nothing can tip over. Thus a building can stand on a few pillars for too long.
  • Very tall falling sections stay in one piece. In building4, the upper tower drops one floor and stays upright. The landing break-up only reacts to hard impacts.
  • Fast debris can pass through thin slabs (above about 18 m/s), because continuous collision detection is off for speed.
  • The generator supports only rectangular room layouts and simple pitched roofs. Reinforcement makes bonds stronger, but it does not add visible beams.
  • Not made: whole-district generation, door swings on plans, transparent glass, dust and sound effects.

9. How to run it

Do these steps from the project folder the-finals/.

  1. Make one building:
    .venv/bin/bgen build bgen/specs/office.yaml --seed 1 --out assets/buildings
  2. Look at the images in assets/buildings/office_1/renders/.
  3. Play a destruction scenario and make a GIF:
    .venv/bin/python -m bgen.sim scenarios/office_columns_out.yaml
  4. Open the result in runs/office_columns_out/.
  5. Start the viewer:
    cd rubble && cargo run --release -p rubble-viewer -- ../assets/buildings/office_1/building.bld

See README.md for set-up, tests and more commands. See DESIGN.md for the full design.

10. Glossary

Anchor
A chunk fixed to the ground. All weight flows to anchors.
Blockout
The rough shape of a building: footprints and floor counts.
Bond, edge, joint
A contact between two chunks, with an area and a strength.
Budget
A fixed limit on work or objects per tick.
Chunk
One pre-cut convex piece of a panel. The smallest part that can break off.
Cluster
A group of connected chunks that moves as one rigid body.
Collider
The shape that the physics engine uses to find contacts.
Connection graph
All chunks (nodes) and all bonds (edges) of a building.
Convex
A shape with no dents. Any straight line between two inside points stays inside.
Feature node
A function that adds one type of part (walls, rooms, roofs…).
Freeze
Turn a still, moving body back into static pieces.
Hit points (HP)
Damage that a chunk can take before it is destroyed.
Panel
A 2D profile plus a thickness. Every structural part is a panel.
Pre-fracture
Cut objects into pieces before play, not during play.
Seed
A number that fixes all random choices. Same seed, same building.
Spec
The YAML file that describes a building.
Static
Fixed in place; the engine does not calculate its motion.
Stress solver
Code that calculates the load on every bond.
Tick
One 1/60 s update of the world.
Utilization
Load ÷ strength of a bond. 1.0 or more means it breaks.
Voronoi cell
The area nearest to one seed point. Used to cut panels into chunks.
